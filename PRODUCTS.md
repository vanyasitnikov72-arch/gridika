# Gridika — линейка продуктов

Все продукты — воксельные 3D-эффекты для сайтов на Tilda на одном движке и в одном стиле: из плоского собирается живая 3D-сцена. Каждый эффект — готовый сниппет для блока T123 (или Zero Block), работает без сервера.

| № | Продукт | Статус |
|---|---|---|
| 01 | 3D QR-морфинг | Готов |
| 02 | Визитка с QR | Готов |
| 03 | Подарок с промокодом | Готов |
| 04 | 3D-логотип из вокселей | Готов |
| 05 | Морф «до / после» | Готов |
| 06 | Таймер акции | Готов |

Данные для вкладок студии и карточек каталога лежат в `apps/fx/src/data/products.ts`. При изменении состава обновлять оба места: этот файл и `products.ts`.

---

## Общие принципы (как у 3D QR)

- **Один движок.** Воксели, ортогональная изометрическая камера, квадратный подиум, плавные переходы (`QrMorphViewer` + сцены в `engine/`).
- **Переход без швов.** Простая форма (плоский QR, плоская картинка, карточка) превращается в детальную сцену, пока движется камера. Подмена геометрии не должна быть заметна. Перед сдачей переход проверяется покадрово.
- **У каждого продукта 3 режима** (палитра или настроение). В витрине переключатель стоит под сценой, ширина у всех одинаковая.
- **Если есть QR,** он всегда сканируется: тёмные модули выровнены по яркости, в режиме QR детали убираются. Проверка — jsQR в браузере во всех режимах и на длинной ссылке.
- **Не только Tilda.** Код — обычный HTML + JS: Tilda (T123), WordPress («Произвольный HTML»), Webflow (Code Embed), Wix («Встроить HTML»), любой HTML-сайт. В окне с кодом — вкладки с инструкцией для каждой платформы. На Wix код работает внутри iframe на служебном домене, поэтому защита по домену сверяет адрес страницы-родителя (`engine/domainLock.ts`). На React/Vue код надо вставлять в HTML-шаблон, а не строкой в компонент.
- **Всё продаётся.** В студии эффект можно собрать и посмотреть бесплатно, а код для Tilda (и картинка) выдаётся только по купленному ключу на этот продукт. Бесплатной версии со значком нет.
- **Производительность:** рендер останавливается вне экрана, держим 60+ FPS на ноутбуке.

## 02. Визитка с QR

**Суть:** объёмная визитка эксперта. На обороте QR, который сохраняет контакт в телефон.

**Что видит посетитель**
- Лицевая сторона: воксельная карточка с именем, ролью, логотипом и иконками соцсетей. Наклоняется за курсором, на телефоне — за гироскопом. По краю пробегает блик.
- По клику или свайпу карточка переворачивается, на обороте собирается 3D QR (используем движок 3D QR, форма — плоская плитка с рельефом).
- QR содержит vCard (имя, телефон, почта, сайт, Telegram): навели камеру — контакт сохранён.
- Кнопки соцсетей при наведении «выдвигаются» из карточки кубиками.

**Настройки в студии:** имя, роль, телефон, почта, сайт, Telegram/WhatsApp, логотип (PNG/SVG), режим.

**Режимы:** Изумруд · Графит · Золото.

**Кому:** эксперты, фрилансеры, агентства, мероприятия (бейджи), страницы «Контакты».

**Технически:** генерация vCard 3.0 → QR. Оборот — сцена из 3D QR без камерного перехода (камера зафиксирована сверху, детали — лёгкий рельеф). Лицевая сторона — воксельная плита + текст текстурой (canvas → texture).

**Сделано (студия):** `engine/cardScene.ts`, `engine/vcard.ts`, `components/CardStudio.tsx`. Вертикальная карточка 54×86, наклон за курсором и блик, переворот кликом или свайпом, QR собирается из кубиков, при показе QR карточка приближается. Кубики Telegram / WhatsApp / сайт выдвигаются при наведении и открывают ссылку. Логотип загружается, без него — монограмма. QR не больше 53×53 модулей: если данных много, из QR по очереди убираются WhatsApp, компания, должность, Telegram, сайт (на лицевой стороне остаются), студия пишет, что не вошло. Скан проверяется jsQR прямо с 3D-кадра.

**Дизайны:** Классика, Минимал, Пиксели, Волна, Две части, Диагональ, Чертёж.

**Цвета (8):** Графит, Изумруд, Золото, Океан, Аметист, Бордо, Терракота, Снег (светлая карточка). Под сценой — кружки-цвета. QR проверен во всех 56 сочетаниях дизайна и цвета.

**Скрытие полей:** у каждого поля, кроме имени, есть «глазик». Скрытое поле не печатается на карточке и не попадает ни в QR, ни в кнопки-кубики.

**Код для Тильды:** `engine/cardEmbedGenerator.ts`. Движок карточки — `embed/cardRuntime.js` (чистый JS без импортов): этот же файл работает в студии и вставляется в код как есть, поэтому на сайте карточка выглядит ровно как в студии. QR и данные считаются заранее, three.js 0.174 грузится с jsDelivr (запасной — unpkg). Код ~36 КБ, логотип уменьшается до 256 px. Ключ Pro работает так же, как у 3D QR. На телефоне карточка наклоняется по гироскопу (Android; iOS требует разрешения — пока не запрашиваем).

## 03. Подарок с промокодом

**Суть:** воксельная подарочная коробка. При открытии из неё собирается скидка, промокод или QR-купон.

**Что видит посетитель**
- Коробка с лентой и бантом стоит на подиуме, слегка покачивается и зовёт нажать.
- По клику (или при прокрутке до блока) лента развязывается, крышка подлетает и переворачивается, вылетает конфетти.
- Из коробки поднимается и собирается из кубиков промокод (например, `GRID20`), процент скидки или QR-купон, ведущий на страницу акции.
- Кнопка «Скопировать промокод» под сценой, после копирования — короткая анимация.

**Настройки в студии:** что внутри (промокод / процент / QR со ссылкой), текст, цвет коробки и ленты, срабатывание (клик / прокрутка), режим.

**Режимы:** Праздник (красная коробка, золотая лента) · Крафт (бумага, бечёвка) · Чёрная пятница (чёрная коробка, неон).

**Кому:** интернет-магазины, акции, подарочные сертификаты, лид-магниты («открой подарок — оставь почту»).

**Технически:** коробка из вокселей (стенки, крышка, лента). Анимация открытия — физика «по рельсам» (заранее заданные траектории + пружина). Текст промокода раскладывается в воксели из пиксельного шрифта, QR — движок 3D QR.

**Сделано:** движок `embed/giftRuntime.js` (один и тот же в студии и в коде для сайта), данные — `engine/giftScene.ts`, студия — `components/GiftStudio.tsx`, код — `engine/giftEmbedGenerator.ts`.
- Коробка 8×8×6 вокселей с лентой и бантом на квадратном подиуме; покачивается и подпрыгивает раз в ~3 с.
- Открытие (~1,5 с): сжатие перед прыжком, бант разлетается, лента сползает, крышка подлетает, переворачивается и падает рядом, конфетти (140 штук с гравитацией), из коробки слева направо собирается награда. Камера плавно отъезжает, чтобы в кадре были коробка и награда.
- Внутри: промокод (текст отрисовывается шрифтом Nunito и раскладывается в кубики — подходит любой язык, до 14 символов), скидка «−N%» или QR-купон на белой подложке (скан проверяется jsQR с 3D-кадра во всех режимах).
- Под сценой: подпись и кнопка «Скопировать промокод» (для QR — «Открыть ссылку»), до открытия — «Нажмите на подарок». Это обычный DOM, работает на любом сайте.
- Открывается по клику или при прокрутке (когда блок виден на 60 %).
- Режимы: Праздник, Крафт, Неон (Чёрная пятница; лента и награда светятся).
- Код для сайта ~30 КБ, высота блока 520 px, ключ на продукт `gift-box`.

## 04. 3D-логотип из вокселей

**Суть:** логотип клиента раскладывается на воксели и собирается в объёмный знак для первого экрана.

**Что видит посетитель**
- При загрузке страницы кубики слетаются и собирают логотип, затем он медленно вращается или покачивается.
- При наведении логотип рассыпается на кубики и тут же собирается обратно. При прокрутке может разлетаться и «уходить» вглубь.
- Тени и свет как у остальных сцен, фон прозрачный, можно поставить поверх любого первого экрана.

**Настройки в студии:** загрузка PNG/SVG, разрешение (сколько вокселей по ширине), глубина (толщина знака), цвета (из логотипа или своя палитра), поведение (вращение / покачивание / статично), режим.

**Режимы:** Глянец (гладкие блестящие кубики) · Матовый (мягкий свет, пастель) · Неон (светящиеся грани на тёмном).

**Кому:** бренды, агентства, стартапы, личные сайты — первый экран, страница «О нас», заставки.

**Технически:** растеризация картинки в сетку (порог по альфе и цвету), каждый закрашенный пиксель — колонка вокселей нужной глубины. Сборка — тот же механизм задержек, что у QR. Цвет — среднее по пикселю, с квантованием палитры.

**Сделано (студия):** `embed/logoRuntime.js` (общий для студии и сайта), `engine/logoScene.ts`, `engine/logoEmbedGenerator.ts`, `components/LogoStudio.tsx`.
- Загрузка PNG / SVG / JPG / WebP до 5 МБ (кнопкой или перетаскиванием); файл не уходит на сервер. Пустые поля обрезаются, у непрозрачных картинок фон определяется по углам и убирается.
- Каждая клетка — 4×4 подпикселя: доля закрашенного ≥ 42 % → кубик, цвет — среднее. Палитра до 10 цветов; полутона по краям (смесь цвета с фоном или двух цветов) сливаются с основным цветом.
- Настройки: детализация 20–64 кубика по длинной стороне, толщина (2 / 4 / 7), цвета из логотипа или один цвет (8 вариантов), движение (покачивание / вращение / статично). Режимы: Глянец (лак и студийные отражения), Матовый (пастель), Неон (светится контур знака, тёмный фон).
- Поведение: кубики слетаются, когда блок впервые появляется на экране; при наведении знак рассыпается и собирается, бугорок бежит за курсором, лёгкий наклон за курсором; клик — снова рассыпать. `prefers-reduced-motion` — без анимаций.
- В код и в ссылку покупки уходит сетка (палитра + строка RLE, демо — ~0,8 КБ в ссылке), а не картинка; готовый код ~20 КБ, фон прозрачный (у неона — тёмный).
- Не сделано: разлёт при прокрутке.

## 05. Морф «до / после»

**Суть:** картинка «до» рассыпается на воксели и собирается в картинку «после». Объёмная замена обычной шторки сравнения.

**Что видит посетитель**
- Показана фотография «до», собранная из мелких кубиков (почти как обычное фото).
- Ползунок, кнопка или прокрутка запускают морф: кубики приподнимаются, перелетают на новые места или меняют цвет и опускаются, собирая «после».
- Можно остановить посередине — видна объёмная «волна» перехода. Ползунок двигает её туда и обратно.

**Настройки в студии:** две картинки («до» и «после»), подписи, разрешение сетки, тип перехода, управление (ползунок / прокрутка / автоплей), режим.

**Режимы:** Волна (переход катится слева направо) · Взрыв (кубики разлетаются и собираются) · Пиксель (каждый кубик переворачивается, как табло).

**Кому:** ремонт и дизайн интерьеров, фитнес и медицина (результаты), тюнинг авто, ретушь, ландшафтный дизайн.

**Технически:** обе картинки → сетки цветов одного размера, один InstancedMesh, у каждого вокселя цвет «до» и «после». Режим «Волна» — задержка по X, «Взрыв» — подъём по дуге, «Пиксель» — поворот кубика на 180°. Сетка до ~80×60 для 60 FPS.

**Сделано (студия):** `embed/morphRuntime.js` (общий для студии и сайта), `engine/morphScene.ts`, `engine/morphEmbedGenerator.ts`, `components/MorphStudio.tsx`.
- Две картинки (JPG / PNG / WebP до 8 МБ, кнопкой или перетаскиванием, файлы не уходят на сервер) обрезаются в одну рамку — пропорции картинки «до», от 3:4 до 16:9 — и усредняются в сетку 48 / 64 / 80 кубиков в ширину. Демо — комната до и после ремонта, нарисована кодом.
- Лицевая грань кубика показывает точный цвет фото (без освещения), бока и верх чуть темнее — в покое это обычная картинка, при переходе видно объём.
- Режимы (6): Волна (фронт слева направо, кубики приподнимаются), Взрыв (разлёт из центра и сборка), Пиксель (переворот рядами сверху вниз, как табло), Спираль (переход закручивается от центра), Дождь (старые кубики осыпаются вниз, новые падают сверху), Мозаика (переворот вразнобой). В студии — значки под картинкой.
- Скорость перехода (медленно / обычно / быстро — для «Сам» и «Прокрутки»), подписи тёмные или светлые, кубики плоские или объёмные.
- Управление: ползунок (стеклянная плашка; ещё перетаскивание по картинке и клавиши-стрелки), прокрутка (пока блок на экране, немного прокрутили вниз — переход проигрывается целиком за ~1,5 с, вверх — обратно; подсказка с мышкой «Прокрутите вниз / вверх — вернуть»), «Сам» (автоплей туда-обратно, плашка с паузой и ходом, клик по фото переключает сразу). Ползунок и плашка «Сам» приглушены (45 %), пока посетитель не навёл курсор, не коснулся блока или не перешёл на него с клавиатуры.
- Телефон: ползунок тянется пальцем; по самому фото переход двигает только свайп вбок — свайп вверх/вниз листает страницу, как обычно. Прокрутка на телефоне работает так же, как колесо мыши (подсказка «Пролистайте вниз»). Подписи «До / После» меняются вместе с переходом, их можно переименовать или убрать.
- Код ~33 КБ (обе сетки в RGB565 base64 внутри), блок держит пропорции (`aspect-ratio`, до 760 px в ширину).
- В ссылке покупки обе сетки: ~22 КБ для 64×48. Браузеры такую ссылку открывают; некоторые почтовые клиенты могут обрезать слишком длинную ссылку в письме — если будет проблема, для морфа давать в письме ссылку на «Спасибо» без картинок и просить загрузить фото в студии заново.

## 06. Таймер акции

**Суть:** обратный отсчёт до старта или конца акции, цифры собраны из вокселей и пересыпаются каждую секунду.

**Что видит посетитель**
- Дни : часы : минуты : секунды крупными объёмными цифрами из кубиков на подиуме.
- Каждую секунду меняющаяся цифра рассыпается и собирается в новую. Остальные стоят, слегка «дышат» светом.
- В конце отсчёта — вспышка, конфетти и надпись «Акция началась» или «Успейте», либо переход по ссылке.
- Под таймером необязательная кнопка («Купить со скидкой»).

**Настройки в студии:** дата и время окончания (с часовым поясом), что показать в конце (надпись / ссылка / скрыть блок), формат (с днями или без), подписи, режим.

**Режимы:** Распродажа (красный и жёлтый) · Запуск (мятный, техно) · Новый год (зелёный и золото, снег).

**Кому:** распродажи, запуски курсов и продуктов, вебинары, мероприятия, предзаказы.

**Технически:** пиксельный шрифт цифр (5×7) → воксели. Смена цифры — кубики старой цифры, которых нет в новой, улетают, новые прилетают, общие остаются. Время считается от абсолютной даты (не зависит от того, когда открыта страница), анимация только при смене разряда.

**Сделано (студия):** `embed/timerRuntime.js` (общий для студии и сайта), `engine/timerScene.ts`, `engine/timerEmbedGenerator.ts`, `components/TimerStudio.tsx`.
- Конец задаётся датой, временем и часовым поясом (Калининград … Камчатка, Лондон, Берлин), хранится как абсолютное время UTC — у всех посетителей один и тот же отсчёт.
- Формат «С днями» (дни : часы : минуты : секунды), «Без дней» (часы до 99 — студия предупреждает, если до конца больше 99 часов) или «Без секунд» (дни : часы : минуты).
- «Свой у каждого»: вместо даты — 1–72 часа с первого визита посетителя; начало запоминается в его браузере (localStorage, ключ по заголовку и длительности — при обновлении кода у вернувшихся отсчёт сохраняется).
- Узкий блок (уже 480 px — телефон, узкая колонка): дни : часы над минуты : секунды, цифры вдвое крупнее; на широком — в одну строку. Перестраивается само при изменении ширины.
- Заголовок над таймером и необязательная кнопка под ним (текст + ссылка) — обычный HTML внутри блока, фон прозрачный.
- Когда время выйдет: надпись (вспышка, конфетти из кубиков и текст), переход по ссылке (через ~1,8 с, только если посетитель был на странице в момент конца) или «Скрыть блок». В студии — «Посмотреть финал ▶».
- Стили (6): Распродажа (красные цифры, жёлтый подиум), Запуск (мятные цифры, тёмный подиум), Новый год (зелёные цифры, золотой подиум, снег из кубиков), Чёрная пятница (чёрные цифры, розовый подиум), Минимал (графит на светлом), Весна (розовые цифры, падающие лепестки). Стоящие цифры слегка «дышат» светом.
- Код ~23 КБ, настройки в ссылке покупки — ~0,5 КБ.

## Порядок разработки (предложение)

1. **Визитка с QR** — ближе всего к готовому 3D QR, быстро даёт второй продукт.
2. **Таймер акции** — простая геометрия, нужен почти каждому лендингу.
3. **Подарок с промокодом** — эффектный, хорош для продаж.
4. **3D-логотип** — нужна обработка картинок (растеризация).
5. **Морф «до / после»** — две картинки и самый тяжёлый переход.

## Цены на сайте (не решены)

В блоке «Цены» (`apps/fx/src/components/sections/Pricing.astro`) — карточка на каждый готовый продукт и «Все эффекты» (один ключ на всё, включая будущие; для студий — пакеты). Вместо цены пока стоит «Скоро», кнопка оплаты — «Оплата появится скоро».

## Ключи (без регистрации)

Покупка разовая, личного кабинета нет. Покупатель получает **ключ** (`GRD1-…`) на почту вместе с чеком (почту собирает платёжный сервис, не мы), вставляет его в окне «Код для Tilda» — студия выдаёт код. Без ключа код и картинка не выдаются. Ключ можно вставлять снова в любой момент.

**Ключ — на продукт:** в ключе записано, что куплено (`qr-morph`, `qr-card`, … или `all` — «Все эффекты»). Ключ от визитки не откроет 3D QR.

**Как устроено:** ключ подписан секретным ключом (ECDSA P-256), сайт проверяет подпись публичным ключом прямо в браузере. Подделать ключ или переписать в нём домен нельзя.

**Защита от пересылки** (код работает у клиента, поэтому это сдерживание, а не полная защита):
- ключ можно выпустить под домен — тогда он работает только для этого сайта;
- любой выданный код привязан к одному домену (+ его поддомены и предпросмотр Тильды tilda.cc); скопированный на другой сайт, он показывает пометку Gridika;
- номер ключа записан в код — видно, чей ключ утёк;
- утёкший ключ отзывается: добавить номер в `apps/fx/src/data/revokedKeys.ts` и выкатить сайт.

**Выпуск ключей** (`apps/fx`):
- `node scripts/license.mjs issue --product qr-card --domain site.ru` — ключ на продукт под сайт (лучшая защита);
- `node scripts/license.mjs issue --product all --any --count 50 > keys.txt` — пачка ключей без домена для магазина цифровых товаров, который сам отправляет ключ после оплаты (покупатель вводит свой домен в студии);
- продукты: `qr-morph`, `qr-card`, `gift-box`, `voxel-logo`, `voxel-morph`, `sale-timer`, `all`;
- `node scripts/license.mjs check GRD1-…` — проверить ключ.

**Секретный ключ** лежит в `apps/fx/.license/private.jwk` (в .gitignore). Сделайте резервную копию в надёжном месте: если он потеряется, новые ключи придётся подписывать новым ключом, а старые перестанут проверяться. Если он утечёт — любой сможет выпускать ключи.

## Что получает покупатель

Продукт — это **ключ**, а по ключу в студии — **код для сайта** (HTML + JS, вставляется в Tilda T123, WordPress, Webflow, Wix, обычный HTML). Файлов и личного кабинета нет.

1. **Оплата** у платёжного сервиса (он же присылает чек по 54-ФЗ).
2. **Страница «Спасибо»** — `gridika.ru/thanks#key=GRD1-…` (сервис перенаправляет сюда после оплаты). Показывает, что куплено и для какого сайта, ключ с кнопкой «Скопировать» и кнопку **«Получить код в студии»**. Без ключа в ссылке — поле «вставьте ключ из письма». Демо: `/thanks#key=demo`.
3. **Письмо с ключом** — шаблон `apps/fx/src/emails/keyEmail.ts` (`renderKeyEmail`), предпросмотр и «Скопировать HTML» — `/email-preview`. Вёрстка таблицами, без картинок.
4. **Студия** принимает ключ из ссылки `/?fx=<продукт>#key=<ключ>`: подставляет ключ, переключает на купленный продукт и открывает окно с готовым кодом. Ключ передаётся после `#` — не уходит на сервер и в аналитику — и сразу убирается из адреса.

**Настройки переживают оплату.** В окне кода перед покупкой — поле «Сайт, где будет стоять блок» (подставляется из ссылки в студии; соцсети и мессенджеры пропускаются — блок стоит на сайте, а QR может вести в Instagram). Студия упаковывает свои настройки в ссылку после `#` (`engine/purchase.ts`): `/thanks#key=…&cfg=…`. Тогда:
- на странице «Спасибо» сразу **готовый код** (`engine/purchaseCode.ts`), «Скопировать код» и вкладки «куда вставить»; студия — вторичная кнопка «Изменить в студии»;
- «Изменить в студии» открывает студию **ровно с теми же настройками**, ключом и окном кода;
- в письме главная кнопка — «Скопировать готовый код» (`readyUrl`), рядом «Изменить в студии».

Логотип визитки в ссылку не помещается (слишком большой) — в готовом коде вместо него монограмма; загрузить логотип можно в студии.

Платёжный сервис должен вернуть покупателя на `/thanks#key=<ключ>&cfg=<настройки>` (ключ — выданный, настройки — из ссылки, с которой ушли на оплату). Кнопка «Купить» пока неактивна: оплата не подключена.

**Визитка — один ключ на одного человека.** В ключ визитки записывается имя (`n`, из `cfg.card.contact.name` при оплате; выдача: `license.mjs issue --product qr-card --domain … --name "Анна Смирнова"`). Студия и страница «Спасибо» отдают код, только если имя на карточке совпадает с ключом: регистр, ё/е, порядок слов и 1–2 опечатки не важны (`nameMatches` в `engine/license.ts`). Телефон, почта, ссылки, цвет и стиль меняются свободно. Ключи визитки без имени (старые и пачки `--any`) подходят для любой карточки — для визитки пачки выдавать не стоит. Для команд — пакет «5 / 10 визиток».

**Что входит в один ключ (все продукты).** Ключ всегда на один продукт и один сайт, навсегда.

| Продукт | Один ключ | Меняется бесплатно |
|---|---|---|
| 01 3D QR | без ограничений на сайте | ссылки, формы, режимы |
| 02 Визитка | один человек (имя в ключе, `n`) | телефон, почта, ссылки, цвет, стиль |
| 03 Подарок | без ограничений на сайте | промокоды, скидки, коробки, подписи |
| 04 3D-логотип | один логотип (отпечаток силуэта в ключе, `f`) | цвета, толщина, детализация, эффекты, движение |
| 05 Морф до/после | одна пара фото (отпечаток пары в ключе, `f`); пакеты 5 и 15 пар | режим, сетка, управление, подписи |
| 06 Таймер | без ограничений на сайте | даты, тексты, кнопка, режимы |
| Все эффекты | всё без ограничений на одном сайте (без `n` и `f`) — цена заметно выше суммы одиночных | всё |

Отпечатки — `engine/fingerprint.js` (общий для студии, страницы «Спасибо» и скрипта): логотип → силуэт 16×16, сравнение по пересечению ≥ 0,75 (тот же знак при другой детализации, цвете, толщине даёт 0,88–0,95, другой знак — 0,1–0,6); пара фото → яркость каждого фото 8×6, сходство ≥ 0,9 (та же пара при другой сетке — 0,999–1, другие или переставленные фото — 0,75–0,8). Ключи без отпечатка (старые, пачки `--any`) подходят к любому содержимому — для логотипа и морфа их выдавать не стоит.

**Выдача по ссылке покупки:** `node scripts/license.mjs issue --cfg "<cfg из /thanks#key=…&cfg=…>"` — продукт, сайт, имя для визитки и отпечаток для логотипа / морфа скрипт берёт из настроек сам. Платёжному сервису достаточно передать в выдачу `cfg` из ссылки, с которой покупатель ушёл на оплату.

Демо-ключи (только для `example.com`): `qr-card`, `qr-morph`, `gift-box`, `voxel-logo`, `voxel-morph`, `sale-timer` — в `emails/keyEmail.ts`; предпросмотр из студии — «Как это будет после оплаты (пример)».
