# Gridika — выпуск обновлений и домен

## Ветки

| Ветка | Что это | Что происходит при push |
|---|---|---|
| `main` | **Прод** — то, что на gridika.ru | проверка ключей → сборка → публикация (`.github/workflows/deploy.yml`) |
| `dev` | Тестовая: здесь копятся доработки и новые продукты | проверка ключей → сборка, **без публикации** (`.github/workflows/ci.yml`); готовую сборку можно скачать в Actions → Artifacts |

Прямо в `main` не коммитим. Порядок:

1. Работаем в `dev` (или в отдельной ветке от `dev`, например `feat/new-product`, и вливаем её в `dev`).
2. Проверяем локально: `pnpm dev` → http://localhost:4321, перед выпуском `pnpm check:release` и `pnpm build`.
3. Push в `dev` → на GitHub зелёная галочка «Check».
4. Pull request `dev → main`, проверка снова зелёная → **Merge**. Через 1–2 минуты обновление на gridika.ru.

Если сборка или проверка упала, публикации не будет: на сайте остаётся прошлая рабочая версия. GitHub Pages меняет сайт целиком и сразу, «полусобранным» он не бывает.

Откат: на GitHub в `main` сделать **Revert** нужного pull request → сайт пересоберётся в прошлое состояние.

## Чтобы покупатели никогда не потеряли доступ

Код, который покупатель вставил на свой сайт, самодостаточен. В нём есть всё нужное, а three.js закреплён на версии 0.174.0 с CDN. Поэтому обновления gridika.ru его не трогают. Риски есть только у студии и страницы «Спасибо», где вставляют ключ, и их стережёт `pnpm check:release` (запускается автоматически в обеих ветках):

- **Секретный ключ подписи** `apps/fx/.license/private.jwk` в git не попадает (`.gitignore`). Сделайте 2 резервные копии: менеджер паролей и флешка или офлайн-диск. Без него нельзя выпускать новые ключи, но проданные продолжат работать.
- **Публичные ключи только добавляются.** `src/data/licensePublicKey.ts` — список, `release/keys.lock.json` — «замок». Удалить или изменить ключ из замка проверка не даст.
- **Никогда не запускать `license.mjs init` повторно** (он и сам откажется). Если секретный ключ утёк: `node scripts/license.mjs rotate` создаст новый, старый публичный останется в списке, все проданные ключи продолжат работать. Затем добавить строку, которую подскажет `check:release`, в `keys.lock.json`.
- **id продуктов вечные** (`qr-morph`, `qr-card`, `gift-box`, `voxel-logo`, `voxel-morph`, `sale-timer`, `all`). Продукт можно убрать из студии, но не удалить и не переименовать его id. Новые продукты добавлять в `products.ts`, в `PRODUCTS` скрипта и в `keys.lock.json`.
- **Отпечатки логотипа и пары фото (`L1`, `M1`) не меняются.** Если понадобится новый алгоритм — добавить `L2`/`M2` рядом, старые оставить: `release/fingerprints.json` это проверяет.
- **Ссылка покупки** `/thanks#key=…&cfg=…` и префикс ключей `GRD1-` не меняются. Новые настройки в `cfg` добавлять с значениями по умолчанию (старые ссылки из писем должны открываться).
- **Отзыв ключа** (возврат денег, утечка): id ключа в `src/data/revokedKeys.ts`, выпустить сайт. Уже вставленный покупателем код не ломается, студия просто перестаёт выдавать по этому ключу новый.

## Первая публикация

1. Создать пустой репозиторий на GitHub (без README, .gitignore и лицензии), **Public** — на бесплатном тарифе Pages работает только с публичными. Секретный ключ в репозиторий не попадает.
2. Залить код: `git push -u origin main` и `git push -u origin dev`.
3. Repo → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Repo → **Actions** → дождаться зелёного «Deploy gridika.ru» (или запустить вручную: Run workflow).
5. Repo → **Settings → Branches → Add rule** для `main`: Require a pull request before merging + Require status checks → «check». Так в прод попадает только проверенное.

## Домен gridika.ru

**У регистратора домена** (DNS-записи для `gridika.ru`), удалив старые A-записи парковки:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |
| CNAME | `www` | `vanyasitnikov72-arch.github.io.` |

**На GitHub:**

1. Защита от перехвата домена: аватар → **Settings → Pages → Add a domain** → `gridika.ru` → GitHub даст TXT-запись `_github-pages-challenge-vanyasitnikov72-arch` → добавить её у регистратора → **Verify**.
2. Repo → **Settings → Pages → Custom domain**: `gridika.ru` → Save (файл `apps/fx/public/CNAME` уже есть).
3. Когда проверка DNS станет зелёной (от минут до 24 часов) → включить **Enforce HTTPS** (сертификат выпускается автоматически, до часа).

Проверка: `nslookup gridika.ru` показывает адреса `185.199.10x.153`; https://gridika.ru открывается с замком; https://www.gridika.ru перенаправляет на https://gridika.ru.

## Версии

CI собирает на Node 20 и pnpm 9 (`pnpm-lock.yaml` версии 9.0). Если локальный pnpm перепишет lockfile в новую версию формата, поднять `version` в `pnpm/action-setup` в обоих workflow.
